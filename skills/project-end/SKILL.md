# 收工

留下可供下次接續的真實專案狀態，以臺灣繁體中文撰寫，除非使用者另有指定。

1. 確認專案根目錄，閱讀現有 `README.md`、適用的 `AGENTS.md`、`TODO.md`、`PROGRESS.md`，盤點本輪實際變更、產出、檢查結果與使用者決策。
2. 更新 `TODO.md`，缺少時建立：勾選確實完成的項目，列出未完成工作、阻礙與優先順序。區分必要後續與選做事項，保留仍有用的既有內容。
3. 更新 `PROGRESS.md`，缺少時建立，記錄更新日期、目前狀態、本輪完成事項與成果位置、重要決策及必要理由、未完成工作、已知問題、待確認事項、下次開工的第一個具體動作與驗收方式。只記錄實際執行的檢查，區分已驗證與仍需人工確認的結果，保留有用歷史。
4. 若原本使用 `目前進度.md`、`任務清單.md`、`工作紀錄.md` 等交接文件，先閱讀並保留；依本次要求更新 TODO.md 與 PROGRESS.md，說明與舊文件的對應，避免矛盾。使用者明確指定沿用舊檔名時遵從其指定。
5. 在專案目錄執行 `git rev-parse --show-toplevel` 與 `git status --short --branch`，顯示目前 Git 狀態，回報分支、已暫存、未暫存及未追蹤檔案。若屬上層 repository，說明實際 Git 根目錄。檔案多時可摘要並指出省略情形。未安裝 Git、不是 repository 或查詢失敗時據實說明。
6. 回覆更新了哪些文件、本輪重點、未完成事項、下次第一步及 Git 狀態。收工本身不包含 Git 初始化、提交、推送、清除變更或繼續執行待辦。
